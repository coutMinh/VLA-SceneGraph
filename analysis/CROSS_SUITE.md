## Findings

1. **Object selection is anchored to the trained position, not to the named object
   (OBJ-swap).** In LIBERO-Object the target always starts in one of two canonical
   slots. When the target and the object in the other slot swapped places, pi0
   failed 9/9. In 7 episodes the first object lifted was the decoy now sitting at
   the trained slot (salad dressing in task 0, alphabet soup in task 1, bbq sauce in
   one task-4 episode). Swapping two other objects cost only 2/9 (OBJ-swap-ctrl
   7/9), so layout novelty alone does not explain the result. This is the Object
   suite's version of Spatial S2 (0/6): the same position shortcut, now with
   visually *distinct* objects.

2. **Language works only when it agrees with a trained object–position pairing
   (OBJ-lang 8/9).** With the scene unchanged, naming the object in the other
   canonical slot succeeded 8/9. In each case the named object sat where it sits in
   its *own* training task. OBJ-swap breaks that pairing and fails completely.
   Together they suggest the instruction selects among memorised
   (object, position) routines rather than grounding the object's identity in the
   image. Spatial S1 (22/27) fits the same reading.

3. **pi0 tracks what it grasps, not where it puts it (GOAL-move).** Moving the bowl
   that has to be picked up ("put the bowl on the stove") left success at 3/3: the
   gripper reached the bowl's new position, within 0.4–6.8 cm of it. Moving the
   destination (the bowl in "put the cream cheese in the bowl", the plate in "put
   the bowl on the plate") gave 1/6. In 3 of the 5 failures the carried object came
   within 0–1 cm of where the destination *had been* (`GOAL-move-t06-s01/s02`,
   `t08-s02`). This was measured from the logged object poses; see the snippet
   below. Moving an irrelevant object did not hurt (8/8).

4. **Sub-goal progress is not read from the scene (LONG-pre, LONG-undo).** Both
   interventions leave a scene where the remaining work is plainly visible, so a
   purely reactive single-frame policy should cope with both.
   - With the first object already in the basket, only 3/9 finished. In 4/9 a
     non-goal object (ketchup, milk, orange juice) was lifted first.
   - When the first object was returned to its start pose after resting in the
     basket (gripper already open), pi0 went on to place the second object in all
     9 episodes. It **never** went back for the first one in the remaining ~250
     steps (0/9).

   The behaviour looks like a learned A→B routine driven by its own phase rather
   than by the current state of the scene. A state such as "B done, A not done"
   never occurs in demonstrations, and the policy does not recover from it. This is
   the Long-horizon counterpart of T1. It differs in one way: here the current
   frame *does* contain the needed information, so the failure is not explained by
   missing history alone.

## Caveats

- Each condition has 9 episodes from 3 tasks; outcomes are clustered by task. The
  p-values are exploratory and correct for neither clustering nor multiple
  comparisons.
- Treatment and control relocate different objects, so their displacements are not
  matched. The source-object/destination split in GOAL-move is a post-hoc reading
  of the three declared task choices.
- Interventions are scripted simulator state edits (pose assignment, teleport).
  They are not robot-executed events.
- Outcome labels come from poses: `first_lifted` means a rise of more than 5 cm.
  The README examples were checked against video; the rest were not.
