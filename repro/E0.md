Implementation is ready for runtime validation. **No new GPU parity or E0 result is
claimed.** Molab resources were exhausted during implementation. The retained 2026-10-28
smoke remains the only completed policy episode. Read `docs/SCENE_PROTOCOL.md` first.

## Layout and fixed workload

- `src/sgvla/eval/scenes.py`: CPU BDDL/NumPy-archive verifier, actual benchmark order,
  filename-derived prompts, per-file and per-state checksums. Generated evidence:
  `results/part2/scene_verification/scene_report.json`, `docs/SCENE_VERIFICATION.md`.
- `manifest.py`: stable IDs `E0-t00-s00` etc.; ten tasks × states 0-4, seed 7;
  policy fingerprint separated from workload settings. States 0-2 form the later paired subset.
- `run_libero.py`, `trace.py`: official preprocessing and action ordering with synchronized
  videos, all object/fixture root poses and complete MuJoCo state.
- `engine.py`, `reporting.py`: atomic validated completion, retries, registry, first-batch
  inspection, per-task rates and Wilson intervals.
- `parity.py`: invokes the actual pinned `eval_libero`, with temporary adapters only at
  suite selection, environment recording and policy connection boundaries.
- `baselines/openpi/seeded.py`: namespaced seed/call requests; explicit 50x32 noise through
  the public `Policy.infer(noise=...)` API. Upstream source is never edited.
- External notebook: `Homework/NganLe/molab/vla_scenegraph/part2_e0.py`.

## Molab run order

Sync this implementation to the code checkout on Molab before using the notebook.
Reuse `SGVLA_WORK=~/vla_scenegraph_work` from the setup notebook. The Python 3.13
notebook/control process invokes the existing Python 3.11 JAX server and Python 3.8
simulator environments. Do not reinstall or redownload when these survive a restart.

```sh
export PYTHONPATH="$SGVLA_WORK/VLA-SceneGraph/src"
python -m sgvla --work "$SGVLA_WORK" init-config
# Use the config path returned by init-config as --config if it differs from the default.
python -m sgvla --work "$SGVLA_WORK" start probe
# Inspect job/log; backend-check must pass before server on a changed runtime.
python -m sgvla --work "$SGVLA_WORK" start backend-check
python -m sgvla --work "$SGVLA_WORK" start eval-plan
python -m sgvla --work "$SGVLA_WORK" start server
python -m sgvla --work "$SGVLA_WORK" start eval-parity
python -m sgvla --work "$SGVLA_WORK" start eval-batch
python -m sgvla --work "$SGVLA_WORK" start eval-review
python -m sgvla --work "$SGVLA_WORK" start eval-all
```

These are separate asynchronous jobs: **wait for each prerequisite to finish** before
starting the next; the server remains running. `status` shows state/log paths. The new
notebook provides these controls, tables, inspection output and both episode videos.
An old server must be stopped/restarted to load the seeded adapter; no new dummy is needed.
The CLI rejects simultaneous evaluation jobs and environment changes while jobs run.

`eval-plan` verifies sources in the actual runtime and creates `$SGVLA_WORK/configs/e0_manifest.json`.
It never overwrites a different existing manifest. `eval_batch_size` in the runtime config
may be 5-10 (default 5). `evaluation_manifest` can select another immutable manifest path.
Only Spatial is enabled; no Object/Goal/Long or Part 3 interventions run implicitly.

## Correctness gate and RNG deviation

Parity runs task 0, initial states 0,1,2. Each selected state gets a fresh wrapper and
fresh official invocation. Both use the same simulator seed and per-task/state policy
noise. Require identical hashes of every policy-call input, equal success/step count,
and all action chunks/executed actions within `atol=1e-5, rtol=0`. This criterion was
fixed in SCENE_PROTOCOL.md before any new GPU run. Differences cause a failed report,
not an automatic tolerance relaxation. Raw arrays, videos and source hashes are retained.

This tests the official loop for the selected episodes, **not its full-suite RNG stream**:
official normally reuses environments per task and advances policy RNG across episodes.
The resumable evaluator uses a fresh environment and deterministic episode/call noise,
so retries and batch order cannot change the requested action noise. Report this deviation.
No action agreement is claimed until the runtime parity report passes.

## Completion, errors and trace schema

Outputs: `$SGVLA_WORK/results/part2/e0/<manifest-hash>/episodes/<episode-id>/attempt-*/`.
Each attempt retains config, full manifest, metrics, numeric trace and both MP4s.
`complete.json` is published atomically only after validation. Resume checks workload,
policy and implementation fingerprints, source state identity, every artifact checksum,
array shapes/finiteness and complete video decoding. Corrupt/incompatible/partial outputs
are retried in a new attempt; old evidence is retained. Completed failures are skipped
just like successes. Each attempt has an idempotent row in `results/registry.csv`;
completion-to-registry crash recovery reconciles missing rows.

Infrastructure exceptions write `error.json`, stop the batch, and leave the episode
pending. They do not enter the success-rate denominator. Restart the server after Molab
restart, then rerun the same action/manifest; never resume an in-flight action chunk.

`trajectory.npz` is loadable with `allow_pickle=False`:

| Array | Alignment / convention |
|---|---|
| `state` | `[F,8]` end-effector xyz, axis-angle, two gripper qpos |
| `actions` | `[F-1,7]`, action from frame i to i+1, includes settling |
| `object_names`, `object_poses` | `[O]`, `[F,O,7]`, world xyz + MuJoCo wxyz quaternion |
| `sim_state` | `[F,D]`, full flattened MuJoCo state; records fixture articulation too |
| `phase` | 0=settling, 1=policy execution, 2=terminal |
| `bowl_on_plate` | `[F,2]`, LIBERO's own On predicates, bowl 1 then bowl 2 |
| `policy_chunks` | `[C,50,7]`, complete returned chunks |
| `policy_call_frames`, `policy_call_seconds` | `[C]`, corresponding frame indices and round-trip time |

Both videos have F frames, including settling and the terminal state; at E0,
`F = 10 + control_steps + 1`. Metrics include policy input hashes and latency samples.
E0 uses the original `done` predicate. S1/S2/T1 are deliberately not enabled: their
target-specific stopping, verified pose interventions and swap history need a later stage.

## First batch and analysis

The evaluator will not cross the first five episodes before `eval-review` succeeds.
Inspection decodes all ten videos, checks all trace arrays, lists task failures, records
latency/runtime/storage, and estimates remaining storage with a 50% margin. It stops if
space is insufficient. `eval-all` runs this inspection automatically at the boundary;
manual review of successful/failed trajectories is still pending Part 3 work.

`eval-status` validates checksums with only stdlib and prints rates/per-task N. A batch's
`summary.json` records the reduced scope and Wilson 95% intervals; these intervals do
not adjust for within-task dependence. Missing/invalid/error episodes remain pending.
Do not publish an incomplete pilot as the 50-episode result. No task outcome is inferred
from source verification or CPU test fixtures.
